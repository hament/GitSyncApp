# 回归测试

这些测试是独立的 Swift 程序，用 `swiftc` 编译后直接运行，不经过 Xcode 的测试计划。需要本机能执行 `xcrun swiftc` 和 `/usr/bin/git`。

除克隆认证脚本会自己切到仓库根目录外，其余命令都在仓库根目录执行。通过时每组打印一行 `PASS:`。断言失败时进程以非 0 退出。编译时 `GitClient.swift` 里的 deprecated `withValue` 警告可以忽略，只要最后出现对应的 `PASS:`。

测试使用临时目录和临时 Git 配置，不修改本机的 `~/.gitconfig`。最近项目测试会读写 `recentRepositoryPaths` 和 `lastRepositoryPath`，结束时恢复原值。

## 一次跑完

```bash
bash Tests/run-clone-auth-regressions.sh

build_dir=$(mktemp -d)
xcrun swiftc -swift-version 6 \
  GitSync/GitSync/Views/BranchListData.swift \
  Tests/BranchListTests.swift \
  -o "$build_dir/branch-list-tests"
"$build_dir/branch-list-tests"
rm -rf "$build_dir"

build_dir=$(mktemp -d)
xcrun swiftc -parse-as-library -swift-version 5 -default-isolation MainActor \
  GitSync/GitSync/AppModel.swift \
  GitSync/GitSync/Localization.swift \
  GitSync/GitSync/Models.swift \
  GitSync/GitSync/Git/*.swift \
  GitSync/GitSync/Store/*.swift \
  Tests/RecentRepositoryTests.swift \
  -o "$build_dir/recent-tests"
"$build_dir/recent-tests"
rm -rf "$build_dir"
```

克隆认证和最近项目会编译 `AppModel` 与 Git 相关源码，第一次会稍慢。编译产物放在临时目录里，跑完即删。

## 克隆认证

```bash
bash Tests/run-clone-auth-regressions.sh
```

脚本连续跑两组，对应 `Tests/run-clone-auth-regressions.sh`。

第一组只编译 `CloneAuthenticationGuide.swift`。检查这些行为：能否识别认证失败，恢复步骤是否只针对 HTTPS，带用户名、密码、token 或片段的地址是否被拒绝，配置命令能否重复执行且只改当前服务器的 helper，以及 shell 引号是否正确。

第二组编译克隆流程。它在本机起一个 HTTP 服务，模拟 401 和 403，不访问真实远程。检查认证失败时是否给出引导、是否保留提交说明、是否不改已有 Git 配置、是否不创建空目录；403 是否不当成认证失败；目标目录里已有文件是否保留；凭据可用后重试能否克隆成功并自动打开仓库。

通过时输出：

```text
PASS: authentication detection, HTTPS-only recovery, secret URL rejection, scoped/idempotent configuration, shell quoting
PASS: HTTPS authentication failure, guide reset, 403 classification, draft preservation, retained destination safety, retry and automatic opening
```

## 分支列表

```bash
build_dir=$(mktemp -d)
xcrun swiftc -swift-version 6 \
  GitSync/GitSync/Views/BranchListData.swift \
  Tests/BranchListTests.swift \
  -o "$build_dir/branch-list-tests"
"$build_dir/branch-list-tests"
rm -rf "$build_dir"
```

检查分支如何分成当前、最近、本地、远程，搜索时如何去重，分离头指针和空列表如何显示，以及一万个远程分支时按名称过滤是否只留下匹配项。

要看真实仓库上的分组和搜索耗时，把仓库路径传给可执行文件，并在删除临时目录之前执行：

```bash
"$build_dir/branch-list-tests" /path/to/repository
```

这一步只读取 `refs/heads` 和 `refs/remotes`，不修改该仓库。通过时先打印固定用例的 `PASS:`，再打印本地与远程分支数量，以及分组、搜索耗时。

固定用例的通过输出：

```text
PASS: grouping, deduplication, search, detached HEAD, empty list, 10,000 branches
```

## 最近项目

```bash
build_dir=$(mktemp -d)
xcrun swiftc -parse-as-library -swift-version 5 -default-isolation MainActor \
  GitSync/GitSync/AppModel.swift \
  GitSync/GitSync/Localization.swift \

```

检查从最近列表移除项目后，列表和最后打开的项目是否一起更新；列表为空时的结果；操作进行中是否拒绝移除；移除记录时是否保留磁盘上的文件和当前提交说明。

通过时输出：

```text
PASS: recent removal, persistence, last-project fallback, empty list, busy guard, local files and current draft preserved
```
