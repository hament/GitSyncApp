# GitSync 开发文档

Mac 端可视化 Git 管理工具。本文描述第一版要做什么、界面怎么排、Git 怎么调用。确认后再按此开发。

当前工程是 `GitSync/` 下的 SwiftUI 模板，界面只有 “Hello, world!”。第一版在这个工程上继续做，只支持 macOS。

## 1. 第一版范围

做这些：

- 选择本机文件夹作为仓库，顶栏显示仓库路径和当前分支
- 切换分支；列表顺序为：当前分支、本应用里曾经选过的分支、其余分支；可按名称搜索
- 从当前提交新建分支并切换过去
- 把另一分支合并进当前分支；冲突留在变更列表里，可完成或中止合并
- 列出当前工作区相对 `HEAD` 的变更文件
- 右键文件：放弃修改、加入 `.gitignore`、在 Finder 中显示、用 VS Code 打开
- 点选变更文件，右侧显示与 `HEAD` 的差异
- 勾选文件后 Commit；以及 Push、Pull、Fetch
- 界面全部为中文。Commit、Push、Pull、Fetch、切换分支、新建分支、合并失败时，弹出警告框，显示失败原因和完整日志
- 提交历史，以及每次提交改过的文件；点文件可看该次提交的差异

第一版不做：

- 删除、重命名分支
- Rebase、cherry-pick、stash、应用内冲突编辑器
- 按行暂存，以及「已暂存 / 未暂存」分栏。勾选以整个文件为单位
- 多仓库侧边栏、子模块、LFS 管理
- Blame、行内评论、语法高亮
- 账号登录、Pull Request、远程仓库浏览

## 2. 技术方案

| 项 | 决定 |
| --- | --- |
| 界面 | SwiftUI，macOS |
| Git | 调用本机 `git`（按 `PATH` 查找，找不到再用 `/usr/bin/git`） |
| 最低系统 | 沿用工程现有部署目标（macOS 26.6） |
| 沙盒 | 关闭 App Sandbox |
| 界面语言 | 中文。按钮、菜单、空状态、确认框、警告框都用中文；分支名、路径和 Git 原始输出保持原样 |
| 本地记录 | `UserDefaults`：最近 20 个仓库、每个仓库最近用过的分支 |

调用系统 `git`，是为了沿用用户本机的 `user.name`、远程地址、SSH、credential helper 和 hooks。不内嵌 libgit2。

关闭沙盒，是因为应用要在任意目录读写工作区和 `.git`、启动 `git`、访问 `~/.ssh` 与钥匙串，并允许 Push / Pull / Fetch 走网络。这是本机开发工具，不准备上架 Mac App Store。

工程目前还声明了 iOS / visionOS。第一版把支持平台收成仅 macOS，并打开用户所选文件的读写与出站网络（沙盒关闭后，网络不再受沙盒开关限制）。

## 3. 界面

一个窗口，三块区域。

```
┌──────────────────────────────────────────────────────────────┐
│ 选择项目   /Users/me/repo          分支 ▾    刷新 Fetch Pull Push │
│                                    [ 变更 | 历史 ]              │
├────────────────────────┬─────────────────────────────────────┤
│ ☐ 变更文件              │  选中文件的 diff                      │
│ 或提交列表              │  或该次提交里选中文件的 diff           │
│                        │                                     │
├────────────────────────┴─────────────────────────────────────┤
│ 提交说明 ______________________________  提交 N 个文件         │
└──────────────────────────────────────────────────────────────┘
```

顶栏：

- **选择项目**：菜单中可以打开系统文件夹选择面板，也可以直接打开最近选择过的 20 个仓库
- 路径：单独显示在操作栏下方一行；显示所选仓库根目录的完整路径，路径过长时中间省略，悬停可看全文
- **分支**：菜单按钮，见第 4 节。菜单底部有「新建分支…」和「合并到当前分支…」
- **刷新**：重新读取状态、分支、当前文件列表
- **Fetch / Pull / Push**：见第 8 节
- **变更 | 历史**：切换左侧列表。提交栏只显示在「变更」页面底部

左侧：

- 「变更」：勾选框、文件路径、状态标记（修改、新增、删除、未跟踪、重命名、冲突）。勾选规则见第 6 节
- 「历史」采用三栏布局：左栏是最近提交的短 hash、说明、作者、相对时间；中栏是所选提交修改的文件；右栏是所选文件的 diff

右侧：

- 未选中时显示空状态文案
- 选中变更文件或某次提交中的文件时，显示统一 diff：删除行、新增行、上下文行

「变更」分栏容器底部：

- 多行提交说明
- Shift + Enter 在当前光标位置换行，Command + Enter 提交
- 按钮文案为「提交 N 个文件」，N 为已勾选的文件数
- 没有勾选、说明为空，或已有 Git 操作在跑时，按钮不可用
- 提交模块宽度跟随左侧「变更」分栏，拖动分栏时同步调整

窗口记住上次的大小。再次启动时打开上次的仓库。

## 4. 分支

数据来自：

- `git branch --format=...`：本地分支，标出当前分支
- `git branch -r`：远程跟踪分支

菜单分组，顺序固定：

1. **当前**：正在检出的分支，一项
2. **最近**：本应用里、这个仓库路径下，用户曾经切换到的分支，最近使用的在前，不含当前分支，最多 8 个
3. **本地**：其余本地分支，按名称排序
4. **远程**：`origin/main` 这种远程跟踪分支，按名称排序。不把 `origin/HEAD` 当作可切换项

搜索框过滤上述全部分组，匹配分支名子串，不区分大小写。没有匹配时显示「没有匹配的分支」。

切换规则：

- 点本地分支：`git switch <name>`
- 点远程跟踪分支：若已有同名本地分支则 `git switch` 到它；否则 `git switch --track <remote>/<name>`
- 工作区有未提交修改，且 Git 拒绝切换时：不丢弃修改，按第 12 节弹出警告框
- 切换成功后，把该分支写入这个仓库的「最近」列表（当前分支本身不重复出现在「最近」里），并刷新文件列表与历史

「最近」按仓库绝对路径分开记。换了一台机器上的另一个目录，互不影响。

菜单底部两项，不参与搜索过滤：

- **新建分支…**：见下文
- **合并到当前分支…**：见第 5 节。处于 detached HEAD 时此项不可用

### 新建分支

从当前 `HEAD` 创建本地分支，并立刻切换过去。

1. 弹出面板：一个名称输入框，按钮「创建并切换」
2. 名称为空白，或 `git check-ref-format --branch <name>` 不通过：按钮不可用，并提示名称不合法
3. 同名本地分支已存在：按钮不可用，并提示已存在
4. 通过后执行 `git switch -c <name>`
5. 成功后关闭面板，顶栏变为新分支，写入该仓库的「最近」列表，并刷新变更与历史
6. 工作区有未提交修改时仍尝试创建。Git 拒绝则保留原分支，按第 12 节弹出警告框

不从指定的其他分支或某条历史提交创建。新分支的起点就是当前所在提交。

## 5. 合并

把另一分支合进**当前分支**。不提供「把当前分支合进别的分支」。

入口是分支菜单底部的「合并到当前分支…」：

1. 面板列出本地分支和远程跟踪分支，分组与搜索规则同第 4 节，不包含当前分支
2. 选中一项后，按钮为「合并到 \<当前分支\>」
3. 点击后确认：「将 \<来源\> 合并到 \<当前分支\>」
4. 确认后执行 `git merge <来源>`。远程分支直接合并 `origin/main` 这种跟踪名，不为此另建本地分支
5. 使用 Git 默认策略：能快进就快进，否则产生一条合并提交。不提供 `--no-ff`、`--squash`

结果：

- 已经最新：提示「已经是最新」，不产生新提交
- 快进或自动合并成功：刷新分支、变更和历史
- 冲突：不在应用内改文件。弹出警告框说明「合并产生冲突，解决后提交以完成合并」，变更列表中这些文件标为「冲突」。可用现有的「用 VS Code 打开」去改
- 工作区不干净导致 Git 拒绝合并：保持原状，按第 12 节弹出警告框

合并进行中（存在 `MERGE_HEAD`）时：

- 顶栏显示「正在合并 \<来源分支\>」
- 底部提交按钮改为「完成合并」。仍只提交已勾选的文件，规则同第 8 节。冲突文件默认勾选。若仍有未解决的冲突，Git 会拒绝，说明保留，并弹出警告框
- 顶栏提供「中止合并」。确认后执行 `git merge --abort`，工作区回到合并前

Detached HEAD 下不能合并，提示先创建或切换到一个分支。

## 6. 变更文件

用 `git status --porcelain=v1 -z` 读取，路径以仓库根为相对路径。

状态展示：

| Git 状态 | 界面 |
| --- | --- |
| 已修改（含已暂存） | 修改 |
| 新文件、已暂存的新文件 | 新增 |
| 删除 | 删除 |
| 未跟踪 | 未跟踪 |
| 重命名 | 重命名，显示新路径 |
| 未合并 | 冲突 |

每一行左侧有勾选框。点勾选框只切换是否纳入下次提交；点整行则在右侧打开 diff，不改变勾选。同一时刻只高亮一个文件。列表标题处有「全选」。

勾选：

- 打开仓库或刷新后新出现的文件，默认勾选
- 刷新后仍在列表里的文件，保持用户上次的勾选状态
- 文件从列表消失后，其勾选状态丢掉

列表在这些时机刷新：打开仓库、切换或新建分支、合并结束或中止、Commit / Pull / Fetch / Push 结束、点击刷新、窗口重新变为前台。刷新时尽量保持当前选中的路径。

### 右键菜单

| 菜单 | 行为 |
| --- | --- |
| 放弃修改 | 见下文。操作前弹出确认框 |
| 忽略文件 | 把该路径追加到仓库根目录 `.gitignore` |
| 在 Finder 中显示 | 在 Finder 中选中该文件 |
| 用 VS Code 打开 | `open -a "Visual Studio Code" -- <绝对路径>` |

**放弃修改**

- 已跟踪文件（修改、删除、已暂存）：`git restore --source=HEAD --worktree --staged -- <path>`，工作区和暂存都回到 `HEAD`
- 未跟踪文件：移到废纸篓，不直接永久删除
- 重命名：恢复新路径上的变更；旧路径按 Git 给出的结果还原
- 冲突文件：同样先确认，再 `git restore --source=HEAD --worktree --staged`。这会丢掉冲突中的两边内容，确认框写明这一点

**忽略文件**

- `.gitignore` 不存在则创建
- 追加一行相对路径。路径里的 `* ? [ ]` 等 gitignore 特殊字符写成转义形式，避免被当成通配
- 若该文件已被 Git 跟踪：写入 `.gitignore` 后仍会出现在变更里。此时再询问是否从索引移除并保留工作区文件（`git rm --cached -- <path>`）。用户拒绝则只保留 `.gitignore` 那一行
- 不自动提交这次 `.gitignore` 改动

**Finder / VS Code**

- 文件已删除、磁盘上不存在时，「在 Finder 中显示」改为显示其所在目录；「用 VS Code 打开」不可用
- 本机没有安装 VS Code 时，提示未找到 Visual Studio Code

## 7. Diff

变更页，选中文件后：

- 已跟踪文件：`git diff --no-ext-diff --no-color HEAD -- <path>`
- 未跟踪文件：把整份文件显示为新增行。用 `git diff --no-index --no-color -- /dev/null <path>`，Git 的 “差异退出码 1” 视为成功
- 二进制文件：不渲染内容，显示「二进制文件，不显示差异」
- 单文件 diff 超过约 2 万行时截断，并提示已截断

历史页，选中某次提交里的文件后：

- `git show -m --first-parent --format= --no-ext-diff --no-color <hash> -- <path>`，合并提交按第一父提交比较

渲染：

- 保留 hunk 头（`@@`）作为弱化的一行
- 以 `+` 开头的行用绿色背景，`-` 用红色背景，其余为上下文
- 左侧显示旧文件和新文件行号；文件头显示新增、删除行数
- 文件头提供 Unified / Split 切换；Split 模式将删除内容放左侧、新增内容放右侧，并按修改块对齐
- 等宽字体，可横向、纵向滚动
- 不解析语法高亮

## 8. Commit、Push、Pull、Fetch

所有 Git 写入和网络操作都在后台执行。执行期间对应按钮不可用，并显示进行中状态。失败时按第 12 节弹出警告框。成功后刷新分支、变更和历史。

环境：

- 工作目录是仓库根
- `GIT_TERMINAL_PROMPT=0`，避免卡在交互式密码输入
- 不使用 `--no-verify`，提交钩子照常运行

**Commit**

只提交勾选的文件，未勾选的留在工作区。

1. 对已跟踪但未勾选的文件执行 `git restore --staged -- <path>`，避免它们因为之前已暂存而被一并提交
2. 对勾选的文件执行 `git add -- <path>`（含未跟踪文件）
3. `git commit -m <说明>`

说明原样作为参数传递，不经过 shell。不使用 `git add -A`。一次提交以整个文件为单位，不能只提交文件中的若干行。

没有勾选、说明只有空白、或已有 Git 操作在跑时，不能提交。钩子拒绝提交时，保留用户已输入的说明和勾选，并弹出警告框。`git add` 已完成但 `git commit` 失败时，同样弹出警告框，并在刷新后反映当前暂存状态。

**Fetch**

- `git fetch --prune`
- 没有 remote 时弹出警告框：「该仓库没有远程」

**Pull**

- `git pull`
- 产生冲突时不自动处理。弹出警告框「拉取产生冲突」，刷新后文件列表会出现「冲突」状态。完成方式与第 5 节的合并相同：改完文件后勾选并提交，或中止
- 本地分支没有上游时，弹出警告框，说明需要先设置上游或先 Push

**Push**

- 已有上游：`git push`
- 没有上游：`git push -u origin <当前分支>`
- 没有名为 `origin` 的远程时，弹出警告框说明无法推送
- 远程拒绝（非快进）时弹出警告框并附上 Git 原文，不强制推送

认证失败或需要登录时，警告框说明请使用系统已配置的 SSH 或 credential helper。本应用不弹出账号密码框。

## 9. 提交历史

历史顶部提供三个范围：

- **当前分支**：当前 `HEAD` 可到达的所有提交，包括被合并分支的提交
- **主线**：使用 `--first-parent`，只显示当前分支主线和合并节点
- **所有分支**：使用 `--all --topo-order`，显示本地与远程跟踪分支的完整拓扑

每次读取最近 100 条。日志同时读取提交 hash、父提交 hash 和 ref decorations。每一行显示说明、短 hash（7 位）、作者、相对时间、Merge 标记和指向该提交的本地/远程分支标签。

提交列表左侧绘制多轨道 Git Graph：不同分支轨道使用不同颜色，分叉和合并通过连接线展示。分支标签只表示当前仍存在的分支指针，不把提交错误标记为永久属于某个分支。

点一条提交：

- 用 `git show --name-status --pretty=format: <hash>` 取该次改动的文件和状态（添加、修改、删除、重命名）
- 用 `git for-each-ref --contains <hash>` 查询当前包含该提交的本地和远程分支，并显示在提交详情中
- 文件列表显示在独立的中栏，并自动选择第一个文件
- 点其中的文件，右栏显示第 7 节的历史 diff

列表底部提供「加载更多」，每次再取 100 条。仓库没有任何提交时，显示「还没有提交」。

## 10. 打开项目

1. 用户选择文件夹
2. 在该目录及其父目录查找 `.git`，找到则把仓库根作为当前项目（允许选中子目录）
3. 找不到 `.git` 时提示「这不是 Git 仓库」，不切换当前项目
4. 成功后记住该路径，读取当前分支、分支列表、变更、历史
5. 再次启动应用，自动打开上次成功的仓库。该路径已不存在或不再是仓库时，停留在空状态，请用户重新选择
6. 每次成功打开仓库后，把路径移到最近项目列表顶部；去重并最多保留 20 个

空状态：说明需要选择一个本地 Git 仓库，并提供「选择项目」按钮。

## 12. 错误与边界

Commit、Push、Pull、Fetch、切换分支、新建分支、合并、中止合并失败时，弹出模态警告框，操作结束后再弹出，不打断后台命令本身。列表保持失败前已加载的内容，随后按第 6 节刷新。

警告框：

- 标题是具体操作，例如「提交失败」「推送失败」「拉取失败」「获取失败」「切换分支失败」「新建分支失败」「合并失败」
- 第一段用中文写失败原因。能从退出码或输出判断时用固定说法，例如「远程拒绝推送」「需要登录」「合并产生冲突」「仓库被锁定，请稍后重试」；判断不了就写「Git 命令执行失败」
- 其下是可滚动、可选择复制的等宽日志，内容为：实际执行的命令、退出码、标准输出、标准错误。Git 输出保持原文
- 按钮为「好」
- 同一次操作只弹一个框。日志过长时截断到末尾约 2000 行，并在开头注明已截断

拉取或合并产生冲突也走这个警告框，因为它需要用户处理。成功、以及「已经是最新」，只用顶栏短暂文字，不弹警告框。

其他边界：

- 当前处于 detached HEAD：顶栏分支名显示短 hash，分支菜单仍可切回某个分支，也可以新建分支；合并不可用。提交按钮可用，Push 在没有上游时按第 8 节提示
- 文件路径含空格、中文：全部使用 `git -z` 或参数数组，不经过 shell
- 放弃修改、忽略已跟踪文件、移到废纸篓、执行合并、中止合并：必须确认。这类确认在操作前出现；操作本身失败后再按上面的警告框显示日志

## 13. 实现顺序
